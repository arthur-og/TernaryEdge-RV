% ABSTRACT
% =============================================================================
\begin{abstract}
Ternary Neural Networks (TNNs) constrain weights to $\{-1, 0, 1\}$, eliminating the need for hardware multipliers and enabling ultra-low-power edge inference. However, most existing TNN accelerators require either standalone FPGA logic without a host OS or tightly coupled custom ASICs. We present \textbf{Ternary Edge-RV}, a full-stack system integrating a multiplierless ternary NPU as a Wishbone peripheral in a LiteX-generated RV32IMA SoC running Linux. The NPU features 64 parallel multiply-accumulate (MAC) units built exclusively from adders and multiplexers (zero DSP slices), a hardware layer sequencer for autonomous multi-layer inference, and a Wishbone Master DMA for direct memory access. Our system achieves a 9.3$\times$ speedup over CPU-only inference on a 3-layer MLP (784$\to$1024$\to$512$\to$256) for MNIST classification, while keeping CPU utilization near zero during NPU compute via interrupt-driven synchronization. The complete design is open-source and synthesizable on entry-level FPGAs.
\end{abstract}

\begin{IEEEkeywords}
Ternary neural networks, RISC-V, FPGA, multiplierless, NPU, edge computing, LiteX.
\end{IEEEkeywords}

Edge artificial intelligence (AI) inference on resource-constrained devices demands architectures that maximize computational efficiency within strict area and power budgets. While CPUs provide flexibility, their general-purpose nature incurs high energy overhead for the repetitive multiply-accumulate (MAC) operations dominant in neural networks. Conversely, dedicated neural processing units (NPUs) achieve superior efficiency but often lack the software ecosystem of a general-purpose OS.

Ternary Neural Networks (TNNs) \cite{ternarynet} offer a unique opportunity: by restricting weights to the set $\{-1, 0, 1\},$ multiplications reduce to conditional additions and subtractions, completely eliminating the need for hardware multipliers. This makes TNNs ideally suited for FPGA deployment where DSP slices are scarce.

This paper presents \textbf{Ternary Edge-RV}, the first full-stack system that integrates a multiplierless ternary NPU into a Linux-capable RISC-V system-on-chip (SoC). Our contributions are:

\begin{enumerate}
    \item \textbf{Multiplierless NPU architecture} with 64 parallel MAC units built exclusively from adders, subtracters, and multiplexers — zero DSP slices required.
    \item \textbf{Wishbone Master DMA} enabling autonomous memory access, freeing the CPU during inference.
    \item \textbf{Hardware layer sequencer} that chains multiple layers without CPU intervention.
    \item \textbf{Full-stack integration} from hardware (LiteX/VexRiscv) through Linux kernel driver to user-space AI application.
\end{enumerate}

\subsection{Ternary Neural Networks}
Ternary Neural Networks \cite{ternarynet, trainedternary} constrain weights to $\{-1, 0, 1\}$, typically using a threshold-based quantization during training:

\begin{equation}
w_q = \begin{cases}
+1 & \text{if } w > \Delta \\
0  & \text{if } |w| \leq \Delta \\
-1 & \text{if } w < -\Delta
\end{cases}
\end{equation}

During backpropagation, the Straight-Through Estimator (STE) \cite{binaryconnect} approximates the gradient of the non-differentiable quantization function.

\subsection{Existing FPGA Accelerators}
Previous work such as FINN \cite{finn} and Larq Compute Engine \cite{larq} demonstrated binary and ternary networks on FPGAs, but either require specialized Xilinx tools (FINN) or lack integration with a full OS. Our approach targets generic Wishbone-based RISC-V SoCs, maximizing portability.

\subsubsection*{The Ternary MAC}
The core computational unit is the \textit{ternary MAC}, which replaces a standard $8$-bit $\times$ $8$-bit multiplier with a conditional adder:

\begin{equation}
P(i) = 
\begin{cases}
+act[i] & \text{if } w[i] = 01\;(+1) \\
0       & \text{if } w[i] = 00\;(0) \\
-act[i] & \text{if } w[i] = 11\;(-1)
\end{cases}
\end{equation}

\subsubsection*{64-MAC Array}
We instantiate 64 ternary MAC units operating in parallel. Every cycle, the NPU fetches four 32-bit words (128 bits total) from the internal weight buffer, unpacking 64 $\times$ 2-bit weights for the MAC array. The 64 partial products are combined through a pipelined adder tree. This yields a theoretical throughput of 64 MAC operations per clock cycle at 50 MHz.

\subsubsection*{Wishbone Master DMA}
Unlike prior PIO-based NPUs, our accelerator includes a Wishbone B4 Master controller that performs burst reads directly from system RAM. The driver programs source and destination addresses via MMIO registers; the NPU autonomously fetches weights and activations, computes all layers, and writes the result back to RAM before raising an interrupt.

\subsubsection*{Layer Sequencer}
A dedicated finite state machine (FSM) iterates through the three dense layers (784$\to$1024, 1024$\to$512, 512$\to$256) automatically. The sequencer reconfigures the DMA controller between layers with zero CPU involvement.

The SoC runs Linux 6.x built with Buildroot. The kernel is configured for RV32IMA with high-resolution timers enabled. The NPU is declared in the Device Tree:

\begin{verbatim}
npu_ternaria: npu@40000000 {
    compatible = "ternaryedge,npu-ternaria";
    reg = <0x40000000 0x00001000>;
    interrupts = <0x0a>;
    interrupt-parent = <&plic>;
};
\end{verbatim}

\subsection{Kernel Driver}
\label{sec:driver}

% --- Gustavo escreve esta subseção ---

The kernel driver implements a Platform Driver that matches against the Device Tree node. Key features include:

\begin{itemize}
    \item \textbf{MMIO mapping:} Registers accessed via \texttt{devm\_ioremap\_resource()}.
    \item \textbf{DMA buffer:} Coherent DMA memory allocated via \texttt{dma\_alloc\_coherent()} for zero-copy weight transfer.
    \item \textbf{Interrupt handling:} \texttt{devm\_request\_irq()} with a wait queue puts the user process to sleep during NPU compute.
    \item \textbf{Character device:} \texttt{/dev/npu\_ternaria} exposes \texttt{open()}, \texttt{mmap()}, \texttt{ioctl()}, and \texttt{release()}.
\end{itemize}

\subsubsection*{Quantization-Aware Training}
We train a 3-layer MLP on MNIST (784$\to$1024$\to$512$\to$256$\to$10) using Larq \cite{larq} with the following specifications:

\begin{itemize}
    \item Weights: ternary ($\{-1,0,1\}$, 2-bit encoding)
    \item Activations: INT8
    \item Regularization: L1 sparsity penalty to maximize zero weights ($> 80\%$ zeros)
    \item Accuracy: $> 95\%$ on MNIST test set
\end{itemize}

\subsubsection*{Weight Packing}
Each 32-bit word packs 16 ternary weights in little-endian order (weight[0] maps to bits $[1:0]$). The encoding is: $+1 = 01_2$, $0 = 00_2$, $-1 = 11_2$.

\subsubsection*{Golden Model}
A C++ simulation of the NPU (\texttt{npu\_sim.cpp}) serves as the bit-accurate golden model for RTL verification.
