# NPU HAL — Hardware Abstraction Layer

C library that abstracts the Ternary NPU for user-space applications. It sits
between the kernel driver and the application, hiding DMA buffer management,
weight loading, and the CPU-side output classification.

Gildo is the current operational owner of the HAL and CPU classifier. Gustavo
owns the AI pipeline maintenance, weight export and `weights.h` contract, the
RV32 cross-compilation workflow, and physical validation coordination. Gilvan's
QAT and ternary-packing work remains historical credit only.

## Architecture

```
user_app (inference + benchmark)
    |
    v  (calls)
NPU HAL (npu_init -> npu_predict -> npu_deinit)
    |  |- npu_classifier (256->10 FP32 output layer)
    |  |- npu_weights    (ternary weights + optional INT32 bias/scale DMA)
    |
    v  (ioctl / mmap)
npu_driver (/dev/npu_ternaria, IRQ, DMA)
    |
    v  (Wishbone bus)
NPU v2 integrated source-level RTL (64 ternary PEs, Layer Sequencer)
```

The canonical RTL integrates 64 ternary PEs, a registered 64-to-1 tree, a
scalar INT32 accumulator, banked activations, a three-stage postprocessor, up
to eight software-programmed descriptors, and 17 MMIO offsets from `0x00`
through `0x40`. Its bounded single-beat Wishbone Classic DMA uses
`CTI=000`, `BTE=00`, downstream `ERR`, and a 256-cycle timeout. Focused Icarus
tests and the 16/32/64-PE matrix pass, including a production-sized
`784->1024->512->256` regression with nonuniform high-row weights: outputs
0..254 equal `65024`, while output 255 equals `-65024`. Verilator lint, generic Yosys synthesis and
`synth_matrix` pass, and the report-gate unit tests pass 12/12.

The HAL's native API and build status are separate from the unverified RV32
cross-build and physical FPGA behavior. Vivado resources and timing, bitstream,
board and Linux boot, physical IRQ/DMA, inference, latency, throughput,
benchmarks, power, and energy remain pending. The historical C++ v2 result of
21/21 is secondary host evidence, not canonical RTL proof.

## Files

| File | Purpose |
|------|---------|
| `npu_hal.h` | Public API declarations |
| `npu_hal.c` | Implementation (init, load_weights, predict, deinit) |
| `npu_hal_internal.h` | `npu_ctx_t` and `npu_result_t` structs |
| `npu_classifier.h` | Classifier API |
| `npu_classifier.c` | Output layer 256->10 FP32 (logits, argmax, softmax) |
| `npu_weights.h` | Weights loader API |
| `npu_weights.c` | Copies ternary weights and optional INT32 bias/scale arrays into DMA |
| `weights.h` | Weight header used for local compilation and export checks |
| `Makefile` | Builds `libnpu_hal.a` |

## Public API

```c
npu_ctx_t   *npu_init(void);
int          npu_load_weights(npu_ctx_t *ctx);
npu_result_t npu_predict(npu_ctx_t *ctx, const uint8_t *image);
void         npu_predict_batch(npu_ctx_t *ctx, const uint8_t *images,
                               int n, npu_result_t *results);
void         npu_deinit(npu_ctx_t *ctx);
void         npu_print_result(const npu_result_t *result, int label);
```

`npu_result_t` carries timing segregation for benchmarking:

| Field | Meaning |
|-------|---------|
| `predicted_class` | Predicted digit (0-9) |
| `confidence` | Softmax confidence (0.0 to 1.0) |
| `logits[10]` | Raw FP32 class scores from the CPU output layer |
| `scores[10]` | Softmax scores per class |
| `time_copy_us` | Time copying the image to DMA |
| `time_npu_us` | Elapsed wait interval around the NPU ioctl, including driver, IRQ, and scheduling overhead; meaningful only after physical validation |
| `time_output_us` | Time of the CPU output layer |
| `time_total_us` | Wall-clock total |

## Build

### Native (syntax/test only)

```bash
cd software/npu_hal
make CC=gcc AR=ar
```

### Cross-compilation (RISC-V target)

Requires the Buildroot toolchain:

```bash
cd software/npu_hal
make CROSS_COMPILE=/path/to/buildroot/output/host/bin/riscv32-buildroot-linux-gnu-
```

## DMA Buffer Layout

Shared with the kernel driver (see `../include/npu_ioctl.h`):

| Offset | Size | Content |
|--------|------|---------|
| `0x000000` | 1 KB | NPU result (256 x INT32 features) |
| `0x001000` | 364 KB | Ternary weights (3 layers) |
| `0x05C000` | 1 KB | Input activations (784 bytes + padding) |
| `0x05F000` | 7 KB | Optional INT32 quantized biases |
| `0x061000` | 7 KB | Optional INT32 scale multipliers |
| `0x062C00` | ~3.8 MB | Free / expansion |

## QAT Pipeline Integration

`weights.h` is generated by the AI pipeline (`ai_training/`) and is ignored by
git. Generated headers set `NPU_MODEL_HAS_QUANT_PARAMS` and contain the INT32
bias/scale arrays used by the RTL. The versioned fallback header predates that
addition and intentionally uses zero bias and identity scale. Its FP32 values
are placeholders, including `0.01` and `0.1`, and are not validated trained
parameters. Gustavo maintains this export contract. Expected arrays:

- `quant_dense_weights[50176]` — Layer 0 (784->1024)
- `quant_dense_1_weights[32768]` — Layer 1 (1024->512)
- `quant_dense_2_weights[8192]` — Layer 2 (512->256)
- `quant_dense_bias[1024]`, `quant_dense_1_bias[512]`, `quant_dense_2_bias[256]`
- `quant_dense_scale[1024]`, `quant_dense_1_scale[512]`, `quant_dense_2_scale[256]`
- `output_weights[2560]` — Output layer FP32 (256 x 10)
- `output_bias[10]` — Output layer bias (current symbol name)
